MCP와
에이전트 생태계

AI에게 손과 발을 달아 주는 표준

이 장에서 다루는 것
  • 에이전트는 목표를 받아 스스로 계획하고 도구를 써서 실행하는 AI다. 혼자 해낼 수 있는 작업의 길이가 빠르게 늘고 있다.
  • MCP는 AI와 외부 시스템을 잇는 공용 규격으로, 1년 만에 경쟁사들까지 모두 채택한 업계 표준이 되었다.
  • 에이전트 도입은 코딩에서 먼저 폭발했다. 다른 업무로 넓히려면 권한 관리와 보안이 핵심 과제다.

AI 비서에게 이렇게 부탁한다고 해 보자. "지난달 지역별 매출을 정리해서 보고서로 만들고, 영업팀 채널에 공유해 줘." 사람에게는 간단한 지시지만 AI가 해내려면 여러 시스템을 거쳐야 한다. 사내 데이터베이스에서 매출을 조회하고, 스프레드시트로 표와 그래프를 만들고, 문서 저장소에 보고서를 올리고, 메신저에 링크를 보내야 한다.

2024년까지는 이런 일을 하려면 AI 서비스마다, 연결할 시스템마다 별도의 연동 코드를 짜야 했다. AI 서비스가 10개이고 업무 시스템이 100개라면 1,000개의 연동이 필요한 셈이다. 이 문제를 푼 것이 이 장의 주인공인 MCP(Model Context Protocol)다. 그리고 MCP가 열어 준 길 위에서 에이전트가 실제 업무 현장으로 들어오고 있다.

4.1에이전트란 무엇인가

에이전트(agent)는 '대리인'이라는 뜻이다. AI 업계에서는 목표를 받아 스스로 계획을 세우고, 도구를 사용해 실행하고, 결과를 확인하며 수정하는 AI를 가리킨다. 질문에 답만 하는 챗봇과 달리, 에이전트는 여러 단계에 걸친 일을 끝까지 수행한다. 에이전트가 일하는 방식은 다음과 같은 반복 고리로 그릴 수 있다.

에이전트는 기존의 업무 자동화(RPA)와도 다르다. RPA는 사람이 미리 정한 절차를 그대로 반복한다. 화면의 버튼 위치가 바뀌거나 예외 상황이 생기면 멈춘다. 에이전트는 목표만 주면 절차를 스스로 짜고, 예상치 못한 상황에서도 방법을 찾는다. 그만큼 유연하지만, 그만큼 예측하기 어렵다는 뜻이기도 하다.

혼자 일할 수 있는 시간이 늘고 있다

에이전트의 실력을 재는 흥미로운 방법이 있다. 비영리 평가기관 METR은 '숙련된 사람이 몇 시간 걸리는 작업을 AI가 절반의 확률로 성공시키는가'를 측정한다. 이 '작업 시간 지평(time horizon)'은 2019년 이후 약 7개월마다 두 배씩 늘어 왔다. 2024년 이후의 최신 모델만 보면 증가 속도가 더 빨라졌다는 분석도 있다. 2024년 중반의 GPT-4o가 사람 기준 몇 분짜리 작업 수준이었다면, 2026년 3월 측정한 Anthropic의 Mythos Preview는 최소 16시간짜리 작업을 절반 확률로 해냈다. 사람으로 치면 이틀 치 업무다.1

물론 METR도 지적하듯 작업 시간 지평이 두 배가 된다고 업무 자동화율이 두 배가 되는 것은 아니다. 측정 과제는 주로 소프트웨어 작업이고, 실제 업무의 모호함과 사람 간 조율은 반영하기 어렵다. 그래도 방향은 분명하다. AI에게 맡길 수 있는 일의 단위가 '한 번의 답'에서 '한나절의 업무'로 커지고 있다.

4.2MCP의 구조

MCP는 2024년 11월 Anthropic이 공개한 개방형 표준이다. 흔히 'AI를 위한 USB-C'라고 부른다. USB-C 이전에는 기기마다 충전기와 케이블이 달랐다. 지금은 규격 하나로 노트북, 휴대폰, 모니터를 모두 연결한다. MCP도 마찬가지다. 업무 시스템 쪽에서 MCP 규격에 맞는 연결 장치를 한 번만 만들어 두면, MCP를 지원하는 모든 AI가 그 시스템을 쓸 수 있다. 앞의 예에서 1,000개(10×100) 필요하던 연동이 110개(10+100)로 줄어드는 셈이다.2

MCP에는 세 가지 역할이 있다. 호스트는 사용자가 쓰는 AI 앱이다. Claude나 ChatGPT, 혹은 회사가 만든 사내 챗봇이 여기에 해당한다. 서버는 업무 시스템 쪽에 붙는 연결 장치로, '매출 조회', '메시지 보내기' 같은 기능을 AI가 쓸 수 있는 형태로 제공한다. 클라이언트는 호스트 안에서 각 서버와 대화를 담당하는 통역사다.

서버가 AI에게 제공하는 것은 크게 세 가지다. 실행할 수 있는 기능인 도구(tools), 읽을 수 있는 자료인 리소스(resources), 자주 쓰는 작업 양식인 프롬프트(prompts)다. 앞의 매출 보고서 예를 다시 보자. AI는 연결된 서버들이 알려 준 도구 목록을 보고 계획을 세운다. 먼저 DB 서버의 '매출 조회' 도구를 호출해 숫자를 받고, 문서 서버의 '파일 만들기' 도구로 보고서를 저장한 뒤, 메신저 서버의 '메시지 보내기' 도구로 링크를 공유한다. 사용자는 이 과정을 지켜보다가 중요한 단계에서 승인만 하면 된다.

4.3표준 전쟁의 결말

기술 표준을 두고는 대개 오랜 전쟁이 벌어진다. 그런데 MCP는 공개된 지 1년 만에 경쟁사들이 모두 받아들인 사실상의 업계 표준이 되었다. 그 과정을 연표로 보자.

  1. 2024.11AnthropicMCP 공개
  2. 2025.3OpenAIMCP 공식 채택. 경쟁사의 표준을 받아들인 상징적 사건
  3. 2025.4GoogleMCP 지원 발표
  4. 2025.9업계공식 MCP 레지스트리(서버 목록) 개설, ChatGPT 앱에 MCP 지원
  5. 2025.11규격비동기 작업, 확장 기능 체계 추가
  6. 2025.12리눅스재단Agentic AI Foundation 출범. MCP 이관
  7. 2026.1규격첫 공식 확장 'MCP Apps'. 대화창 안에 대화형 화면 표시
  8. 2026.4AAIF뉴욕에서 첫 MCP 개발자 회의, 약 1,200명 참석
  9. 2026.7규격대규모 개정안. 서버 운영을 단순하게 하는 구조로 변경

전환점은 2025년 12월이었다. Anthropic, OpenAI, Block이 리눅스재단 산하에 Agentic AI Foundation(AAIF)을 공동 설립하고, 각자의 핵심 프로젝트를 넘겼다. Anthropic은 MCP를, OpenAI는 코딩 에이전트에게 프로젝트 규칙을 알려 주는 안내 파일 규격인 AGENTS.md를, Block은 오픈소스 에이전트 goose를 내놓았다. AWS, 구글, 마이크로소프트, 블룸버그, 클라우드플레어도 최상위 회원으로 참여했다.3 특정 회사의 기술이 아니라 업계 공동 자산이 된 것이다. 리눅스와 쿠버네티스 같은 인터넷의 핵심 인프라가 걸어온 길과 같다.

경쟁사들이 왜 협력했을까. 연결 표준은 많은 회사가 쓸수록 가치가 커진다. 모든 업무 시스템이 하나의 규격으로 AI와 연결된다면 AI 시장 전체가 커지고, 각 회사는 모델의 성능으로 경쟁하면 된다. 반대로 표준이 여럿으로 쪼개지면 업무 시스템 회사들은 어느 쪽에도 투자하기를 망설이고, 시장 전체의 성장이 늦어진다. 인터넷 초기 회사들이 웹 표준을 함께 만든 것과 같은 계산이다.

MCP와 A2A

MCP와 함께 자주 언급되는 표준이 구글이 시작한 A2A(Agent2Agent)다. 역할이 다르다. MCP가 에이전트와 도구·데이터를 연결한다면, A2A는 에이전트와 다른 에이전트를 연결한다. 예를 들어 우리 회사의 구매 에이전트가 협력사의 판매 에이전트와 견적을 주고받는 상황이 A2A의 영역이다. 두 표준은 경쟁 관계가 아니라 보완 관계이며, A2A도 2025년 6월 리눅스재단으로 넘어갔다.4

4.4기업 도입 현황

2026년 중반 기준으로 실제 운영 중인 MCP 서버는 1만 개를 넘었고, MCP 개발 도구의 월간 다운로드는 9천만 건을 넘어섰다는 집계가 있다.2 Claude, ChatGPT, Gemini, 마이크로소프트 Copilot, 그리고 주요 개발 도구가 모두 MCP를 지원한다. 사용자가 어떤 AI를 쓰든 같은 업무 시스템에 연결할 수 있게 된 것이다.

업무 소프트웨어 회사들도 빠르게 움직였다. 마이크로소프트는 2025년 11월 영업·고객 서비스·ERP 시스템인 Dynamics 365용 MCP 서버를 내놓았다. 세일즈포스는 자사 AI 에이전트 플랫폼의 상호작용을 MCP로 처리하기 시작해, 2026년 5월 말까지 MCP 호출 450만 건을 기록했다고 밝혔다. 2026년 1월 공개된 MCP Apps 확장에는 Asana, Box, Canva, Figma, Slack, 세일즈포스 등이 참여했다. 이제 AI 대화창 안에서 디자인 시안을 바로 고치거나 프로젝트 일정표를 조작할 수 있다.5

기업 도입을 가로막던 큰 장벽은 인증과 권한 관리였다. 직원 수천 명이 각자 AI에 업무 시스템을 연결하면 IT 부서는 누가 어떤 시스템에 어떤 권한으로 접근하는지 파악할 수 없다. 2026년 로드맵은 이 문제를 최우선 과제로 삼았다. 회사가 이미 쓰는 통합 로그인 체계로 MCP 접근을 중앙에서 관리하는 기업용 인증 확장이 하반기에 정식 단계에 올랐다.6

4.5코딩 에이전트가 먼저 바꾼 것

에이전트가 가장 먼저, 가장 크게 자리 잡은 곳은 소프트웨어 개발이다. 이유는 세 가지다. 첫째, 코드는 텍스트이고 개발 도구는 이미 명령어로 조작하게 되어 있어 AI가 다루기 쉽다. 둘째, 코드는 실행하고 테스트하면 맞았는지 틀렸는지 바로 확인된다. 에이전트가 스스로 실수를 발견하고 고칠 수 있다. 셋째, 개발자는 새로운 도구를 가장 빨리 받아들이는 사람들이다.

2025년 2월 출시된 Anthropic의 Claude Code가 이 흐름을 열었다. 이어 OpenAI의 Codex, 구글의 Antigravity, AI 코드 편집기 Cursor, 깃허브 Copilot의 에이전트 기능이 경쟁에 뛰어들었다. 시장 규모도 빠르게 커졌다. Anthropic은 2026년 2월 Claude Code의 연환산 매출이 25억 달러를 넘었다고 밝혔다.7 JetBrains가 2026년 중반 개발자를 대상으로 한 조사에서 업무에 쓰는 AI 코딩 도구는 Claude Code(39%), GitHub Copilot(21%), OpenAI Codex(16%), Cursor(12%) 순이었다.8

더 흥미로운 변화는 개발자가 아닌 사람들에게서 일어났다. 2025~2026년 겨울을 지나며 기획자, 마케터, 디자이너들이 코딩 에이전트로 직접 업무 도구를 만들기 시작했다. 원하는 것을 말로 설명하면 AI가 코드를 짜 주는 이른바 바이브 코딩(vibe coding)이다. 엑셀 매크로를 대신하는 작은 웹 앱, 반복 보고서를 자동으로 만드는 스크립트, 고객 데이터를 정리하는 도구처럼, 예전이라면 개발팀 요청 목록에서 몇 달을 기다려야 했던 일들이다.

코딩 에이전트는 개발자의 일을 바꿨고,
비개발자에게는 새로운 일을 열어 주었다.

개발자의 역할도 달라지고 있다. 코드를 한 줄씩 직접 쓰는 시간은 줄고, 무엇을 만들지 정확히 정의하고 AI가 만든 결과를 검토하고 설계를 판단하는 시간이 늘었다. 여러 에이전트에게 동시에 일을 나눠 맡기고 관리하는 '에이전트 관리자'에 가까워진 셈이다. 코딩에서 일어난 이 변화는 다른 사무직 업무에서 앞으로 일어날 일의 예고편이다(13장 참고).

4.6도입의 실제와 보안

1장에서 본 숫자를 다시 떠올려 보자. 절반 넘는 기업이 에이전트를 '운영 중'이라고 답했지만, 효과를 측정하는 곳은 넷 중 하나였다. 사람의 개입 없이 일을 처리하는 진짜 자율 에이전트를 갖춘 곳은 10% 안팎이었다. 현재 '에이전트'라는 이름을 단 시스템의 상당수는 실제로는 정해진 흐름을 따르는 AI 보조 도구다.

에이전트가 잘 작동하는 업무에는 공통점이 있다. 목표가 명확하고, 결과가 맞았는지 확인할 수 있고, 실수해도 되돌릴 수 있는 일이다. 코드 수정, 데이터 정리, 자료 조사, 초안 작성이 여기에 해당한다. 반대로 송금, 계약, 고객에게 나가는 공식 연락처럼 되돌리기 어려운 행동에는 반드시 사람의 승인 단계를 두는 것이 현재의 정석이다.

사례

이슈 글 하나로 비공개 코드가 새어 나가다

2025년 보안 연구자들은 널리 쓰이던 깃허브 MCP 서버에서 심각한 문제를 찾아냈다. 공격자가 공개 저장소에 '이슈' 글을 하나 올리고, 그 안에 AI에게 내리는 지시를 숨겨 둔다. 사용자가 에이전트에게 "새로 올라온 이슈를 확인해 줘"라고 하면, 에이전트는 이슈를 읽다가 숨겨진 지시를 따르게 된다. 그리고 사용자의 비공개 저장소 내용을 공개된 곳으로 옮겨 버린다.9

이것이 프롬프트 인젝션(prompt injection)이다. AI가 읽는 데이터 안에 명령을 숨겨 AI를 조종하는 공격이다. 에이전트는 사용자의 권한으로 행동하기 때문에, 조종당한 에이전트는 사용자가 할 수 있는 모든 일을 할 수 있다. 같은 해 9월에는 정상 서비스처럼 위장해 이메일을 몰래 빼돌리는 악성 MCP 서버가 처음 발견되었다. 미국 국가안보국(NSA)은 2026년 보고서에서 MCP의 확산 속도가 보안 체계의 발전 속도를 앞질렀다고 경고했다.10

체크리스트

MCP·에이전트 도입 전 보안 점검 6가지

  1. 검증된 서버만 쓴다. 공식 제공사나 보안 검토를 거친 MCP 서버만 허용 목록에 올린다.
  2. 최소 권한을 준다. '읽기'만 필요한 일에 '쓰기·삭제' 권한을 주지 않는다. 작업이 끝나면 권한이 만료되게 한다.
  3. 되돌릴 수 없는 행동은 사람이 승인한다. 송금, 외부 발송, 삭제, 결제는 자동 승인 대상에서 뺀다.
  4. 외부 데이터를 믿지 않는다. 웹 페이지, 이메일, 외부 문서를 읽는 에이전트는 인젝션 공격에 노출된다고 가정한다.
  5. 모든 행동을 기록한다. 어떤 에이전트가 언제 무엇을 했는지 감사 기록을 남긴다. 규격이 아직 이를 표준화하지 않았으므로 직접 설계해야 한다.
  6. 설정 변경도 검토한다. MCP 서버 추가와 설정 변경은 코드 변경과 같은 수준으로 검토한다.
핵심 정리
  • 에이전트는 '목표 이해 → 계획 → 도구 사용 → 관찰 → 수정'을 반복하며 여러 단계의 일을 끝까지 수행하는 AI다. 혼자 해낼 수 있는 작업의 길이는 몇 달마다 두 배씩 늘고 있다.
  • MCP는 AI와 업무 시스템을 잇는 공용 규격으로, 호스트·클라이언트·서버의 세 역할로 이루어진다.
  • 2025년 12월 MCP가 리눅스재단 산하 AAIF로 넘어가면서 OpenAI, 구글, 마이크로소프트까지 참여하는 업계 공동 표준이 되었다. 에이전트 간 연결은 A2A가 맡는다.
  • 에이전트는 코딩에서 먼저 자리 잡았고, 비개발자의 '바이브 코딩'으로 퍼지고 있다.
  • 에이전트의 가장 큰 위험은 프롬프트 인젝션과 과도한 권한이다. 최소 권한, 사람의 승인, 감사 기록이 도입의 전제 조건이다.
